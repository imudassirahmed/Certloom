Hypotheses, not verified defects: the large repeated hero on record details may push common actions below the fold; navigation on narrow screens is horizontally scrollable and should be checked with keyboard/screen reader; 42 certificate templates may overwhelm first-time users; actual email-client responsiveness could differ from browser preview. Provider, Elementor, LMS, WordPress-version, printing and large-data restore matrices were not available on this single-plugin site. No claim is made that every possible click, state or accessibility requirement has been certified.

**Workflow judgment:** the main navigation now separates the tasks a new admin recognizes—issue/manage Credentials, optionally organize Programs, then Design/Automations/Settings. The necessary first-credential path is Recipient → credential details → server Review → Issue → view/share/verify. Program, Batch, Issuer and Signer are optional context, and the quick-create controls should remain available at the point of need. The six-step issuance UI still allocates whole steps to optional Context, Certificate and Email decisions. A simpler future treatment would preselect safe defaults, keep those controls expandable on one reviewable page, and show only questions that the chosen mode requires. That redesign has not been built or user-tested; the current successful browser path proves task completion, not that the hierarchy is optimal. Next usability proof should time first issuance, a Program-backed cohort, an independent credential, correction/reissue, CSV import and recovery with new administrators; track points where they backtrack or seek help.

The proposed Free/Pro boundary is a product recommendation, not a gate implemented in this pass:

| Free plugin | Candidate separately distributed Pro add-on | Downgrade rule |
|---|---|---|
| Setup, one-off issuance, Recipients, Programs, basic Issuer/Signer/Batch context, credential status, public verification, privacy controls and complete backup/restore | Bulk issuance and import scale tools | All issued credentials, recipients and verification continue working in Free; imported data remains exportable. |
| At least one usable certificate/email design path and manual email delivery | Advanced design packs, conditional delivery automation, scheduling and analytics | Published designs and already-issued records remain readable and public verification remains intact. |
| Local manual workflows and documented integration extension points | Dedicated LMS/e-commerce/provider connectors and managed delivery services | Disconnecting Pro stops future sync without deleting local credential history. |

Do not transfer an existing feature until its add-on boundary, migration, downgrade behavior, data ownership and support promise are explicit. The [WordPress.org plugin guidelines](https://developer.wordpress.org/plugins/wordpress-org/detailed-plugin-guidelines/) prohibit locked trialware functionality in a directory plugin, recommend externally hosted add-ons for premium code, and require consent for external tracking. This is my inference for a compliant tier architecture, not a statement that the current alpha is directory-ready. No existing feature was gated in this pass.
