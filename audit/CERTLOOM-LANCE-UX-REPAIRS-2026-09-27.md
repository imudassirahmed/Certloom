## Required fields and workflow recommendations

Quick setup currently requires an Issuer name, recipient name, credential title and effective date (pre-filled). Logo, website/contact, recipient email and advanced organization/design choices remain optional for the default details-only path. A chosen design can introduce its own data requirements. The standard issuance path demonstrated that Program, Batch, Signer and artwork are not necessary for an independent credential; a Batch belongs to a Program when used. Design creation requires a name; description is optional and the internal key is generated in Simple mode.

The reduced quick setup is the better starting route for a user who only needs one credential. The ordinary six-step issuance path still exposes separate Context, Certificate and Email decisions for a simple details-only case. A follow-up simplification should combine optional choices behind an expandable section while retaining the server review and per-design required-data checks. This is a design recommendation, not proof that the hierarchy is optimal or a change made in this patch. Validate it with first-time users and both independent and Program/Batch scenarios before replacing the current path.

No Free feature was moved to Pro, no new license gate was introduced, and this UI pass does not claim WordPress.org policy approval. Existing Free/Pro recommendations and unresolved packaging decisions remain in the earlier audit. Provider access for Credly, Coursera and licensed LearnDash is still pending the user's submitted business-email requests; no duplicate provider requests were sent.
