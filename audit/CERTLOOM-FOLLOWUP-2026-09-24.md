## Screen hierarchy and Free/Pro recommendation

Keep six top-level sections: Home, Credentials, Programs, Design, Automations and Settings. Keep **Issue credential** as the primary Credentials action. Keep Recipients, Batches, Issuers and Signers contextual. Keep Import / issue from file as a choice screen until the dual registries are migrated. Put Backup & Restore under Settings with an explicit coverage statement until one complete recovery path exists. Default the credential detail to human actions; put immutable IDs, renderer state and migration diagnostics in expandable Technical details. These changes were evaluated against the live screens, but the detail-page restructuring is a recommendation, not a completed code change.

The current repository has no enforceable, documented commercial entitlement contract or separate Pro add-on. The free plugin should remain complete for Setup, one-off issuance, recipient and Program management, basic design, public verification, privacy controls and **complete** backup/recovery. A separately distributed add-on could own advanced batch automation, bulk scale, provider integrations, advanced analytics and specialized design rules once those boundaries are documented. Existing issued records must remain readable and verifiable when the add-on is absent. Avoid placing paid-but-locked local code in the WordPress.org plugin; guideline 5 disallows trialware and recommends a separate add-on for premium code. Service integrations need clear opt-in/data disclosure under guidelines 6–7; admin upsells must respect guideline 11. The source is the [WordPress.org Detailed Plugin Guidelines](https://developer.wordpress.org/plugins/wordpress-org/detailed-plugin-guidelines/). No current feature was silently removed or gated during this audit because there is no approved migration/downgrade contract.
